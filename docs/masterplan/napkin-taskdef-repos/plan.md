# Napkin & Taskdef as Optional Separate Repos — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let napkin (shared team notes) and taskdef (task templates) optionally live in their own git repos — cloned into stable in-container paths (`/napkin`, `/taskdef`) with `~/work` and `~/napkin` symlinks — while falling back to subdirs of the work repo when unset.

**Architecture:** The host CLI (`lmer_cli.cli`) reads new `LMER_NAPKIN_*` / `LMER_TASKDEF_*` env vars, bakes auth tokens into the repo URLs host-side (mirroring the work-repo pattern), computes the in-container napkin path, and forwards only the *credentialed URLs* into the container. The standalone container entrypoint (`clone_and_exec.py`) clones the optional repos and creates idempotent home symlinks. The in-container `work commit` verb gains a napkin-push step for separate-repo mode.

**Tech Stack:** Python 3 (stdlib only in the container module), pytest, git, Docker/Podman.

## Repo Context

Two repos are involved. **Be explicit about which repo you are in for every task.**

## Global Constraints

Every task's requirements implicitly include this section.

- **Token vars are host-side only.** `LMER_NAPKIN_TOKEN` / `LMER_TASKDEF_TOKEN` are consumed on the host and baked into the repo URL. They are **never** forwarded into the container. Because the `.env` merge in `cli.py` forwards *any* `.env` key not already present in the env dict, each token var **must be seeded `None`** in the env dict to block leakage.
- **Only credentialed URLs cross into the container.** `LMER_NAPKIN_REPO` / `LMER_TASKDEF_REPO` placed in the container env carry their own `oauth2:<token>@` auth, because the container clone (`ensure_clone`) takes no token argument.
- **Napkin/taskdef clone failures are non-fatal** — warn to stderr and continue (matching the secondary-MR clone pattern).
- **Symlink creation is idempotent** — service mode may re-enter the entrypoint, so unlink/replace any existing path before `symlink_to` rather than letting it raise `FileExistsError`.
- **Agents always reference `$LMER_NAPKIN_PATH`** — separate-repo vs subdir mode is transparent to them.
- **`clone_and_exec.py` is standalone** — it must not import from `lmer_cli` or `work_repo`. Use stdlib only.
- **Env-var convention (§4):** every new user-visible `LMER_` var gets a bullet in `docs/LMER-CLI.md` **and** a source-guard test asserting container-bound vars are declared in the cli.py env dict.
- **No AI attribution** in commit messages or napkin notes (no `Co-Authored-By`, no "Generated by" lines).
- **Run the full suite with `make test`** before each commit; run individual tests during the red/green TDD loop with `python -m pytest <nodeid> -v` (same project venv `make test` uses).

```python
def _get_gitlab_token(
    host: str, *, for_work_repo: bool = False, dedicated_env: str | None = None
) -> str | None:
    """
    Look up an API token for ``host`` from environment variables.

    Despite the historical name, this function supports both GitLab and
    GitHub hosts. Lookup order:

    0. ``dedicated_env`` — when given, the named env var is checked first
       (used by napkin/taskdef: ``LMER_NAPKIN_TOKEN`` / ``LMER_TASKDEF_TOKEN``).

    For work-repo lookups (``for_work_repo=True``), check next:
      1. ``LMER_WORK_REPO_TOKEN`` — provider-agnostic dedicated work-repo token
      2. ``GITLAB_TOKEN_worklog`` — deprecated; kept as fallback

    Then, for any lookup:
      3. ``GITLAB_TOKEN_{sanitized_host}`` — host-specific token (provider
         doesn't matter; the name is historical)
      4. For github.com / *.github.com / *.ghe.com: ``GH_TOKEN``, then
         ``GITHUB_TOKEN``
      5. ``GITLAB_TOKEN`` — generic fallback

    Returns the token string, or ``None`` if nothing matches.
    """
    if dedicated_env:
        token = os.environ.get(dedicated_env)
        if token:
            return token

    if for_work_repo:
        token = os.environ.get("LMER_WORK_REPO_TOKEN")
        if token:
            return token
        token = os.environ.get("GITLAB_TOKEN_worklog")
        if token:
            return token

    suffix = _sanitize_hostname(host)
    token = os.environ.get(f"GITLAB_TOKEN_{suffix}")
    if token:
        return token

    if _is_github_host(host):
        for var in ("GH_TOKEN", "GITHUB_TOKEN"):
            token = os.environ.get(var)
            if token:
                return token

    return os.environ.get("GITLAB_TOKEN")
```

```python
def _credential_repo_url(url: str, *, dedicated_env: str | None = None) -> str:
    """
    Bake auth into a napkin/taskdef repo URL host-side (SSH or HTTPS).

    Mirrors the work-repo credentialing: the token is consumed on the host and
    baked into the returned URL, so the URL is cloneable as-is inside the
    container (where the standalone clone script has no token argument). Checks
    ``dedicated_env`` (e.g. ``LMER_NAPKIN_TOKEN``) first, then falls back to
    host-based lookup via :func:`_get_gitlab_token`.

    - SSH ``git@host:path`` -> ``https://oauth2:TOKEN@host/path.git`` when a
      token is available, unless ``REPO_AUTH_PREFER_SSH`` is set.
    - HTTPS with no embedded creds -> token injected as ``oauth2:TOKEN``.
    - Returned unchanged when empty, already credentialed, or no token is found.
    """
    if not url:
        return url

    # SSH form
    if url.startswith("git@"):
        if _prefer_ssh():
            return url
        after_at = url[4:]
        if ":" not in after_at:
            return url
        host, path = after_at.split(":", 1)
        token = _get_gitlab_token(host, dedicated_env=dedicated_env)
        if not token:
            return url
        if not path.endswith(".git"):
            path = f"{path}.git"
        return f"https://oauth2:{token}@{host}/{path}"

    # HTTPS form
    if not url.startswith("https://"):
        return url
    parsed = urlparse(url)
    if parsed.username or parsed.password:
        return url
    token = _get_gitlab_token(parsed.hostname, dedicated_env=dedicated_env)
    if not token:
        return url
    path = parsed.path
    if not path.endswith(".git"):
        path = f"{path}.git"
    return f"https://oauth2:{token}@{parsed.hostname}{path}"
```

`urlparse` and `_prefer_ssh` are already imported/defined in `tokens.py` — no new imports needed.

```python
def link_into_home(link: Path, target: Path) -> None:
    """Idempotently point *link* at *target* (unlink-if-exists, then symlink).

    Service mode can re-enter the entrypoint over a container's lifetime, so a
    stale link/file/dir at *link* is removed first rather than letting
    ``symlink_to`` raise ``FileExistsError``. Best-effort: failures warn.
    """
    try:
        if link.is_symlink() or link.exists():
            if link.is_symlink() or link.is_file():
                link.unlink()
            else:
                shutil.rmtree(link)
        link.symlink_to(target)
    except OSError as e:
        print(f"⚠️  Failed to link {link} -> {target}: {e}", file=sys.stderr)


def setup_napkin_and_links(
    work_repo_path: Path,
    napkin_path: Path,
    *,
    napkin_is_separate: bool,
    home: Path,
) -> None:
    """Ensure the napkin dir exists (subdir mode) and create stable home links.

    - Subdir mode (napkin under the work repo): ``mkdir -p`` the napkin dir so
      ``~/napkin`` is not a dangling link before the first write.
    - Always: idempotent ``~/work`` -> work repo and ``~/napkin`` -> napkin path.
    """
    if not napkin_is_separate:
        try:
            napkin_path.mkdir(parents=True, exist_ok=True)
        except OSError as e:
            print(f"⚠️  Failed to create napkin dir {napkin_path}: {e}", file=sys.stderr)
    link_into_home(home / "work", work_repo_path)
    link_into_home(home / "napkin", napkin_path)
```

```python
def push_napkin_if_separate(commit_message: Optional[str] = None) -> int:
    """
    Commit and push the napkin repo when it is a *separate* git repo.

    Napkin is pushed only when ``LMER_NAPKIN_PATH`` resolves to a git repo that
    lives *outside* ``LMER_WORK_REPO_PATH``. In subdir mode (napkin under the
    work repo) the work-repo commit already captures it, so this is a no-op.

    Runs the same fetch -> pull -> add -> commit -> push flow as the work repo,
    against the napkin repo root. Returns 0 when there is nothing to do or the
    push succeeds; the failing git exit code otherwise. Callers treat any
    failure as a warning — napkin push must never block the worklog commit.
    """
    napkin_path_str = os.environ.get("LMER_NAPKIN_PATH")
    if not napkin_path_str:
        return 0
    napkin_path = Path(napkin_path_str).resolve()
    work_repo_path = Path(os.environ.get("LMER_WORK_REPO_PATH", "/work")).resolve()

    # Separate-repo mode only: a git repo that is not the work repo or under it.
    if not (napkin_path / ".git").exists():
        return 0
    if napkin_path == work_repo_path or work_repo_path in napkin_path.parents:
        return 0

    print("📥 Fetching latest changes from napkin repository...")
    rc, output = run_git_command(["fetch"], napkin_path, check=False)
    if rc != 0:
        print(f"⚠️  git fetch warning (napkin): {output}", file=sys.stderr)

    print("📥 Pulling latest changes from napkin repository...")
    rc, output = run_git_command(["pull"], napkin_path, check=False)
    if rc != 0:
        print(f"⚠️  git pull warning (napkin): {output}", file=sys.stderr)

    print("➕ Staging all changes in napkin repository...")
    rc, output = run_git_command(["add", "-A"], napkin_path, check=False)
    if rc != 0:
        print(f"⚠️  git add failed (napkin): {output}", file=sys.stderr)
        return rc

    rc, status_output = run_git_command(["status", "--porcelain"], napkin_path, check=False)
    if not status_output.strip():
        print("✅ No changes to commit in napkin repository")
        return 0

    if commit_message is None:
        commit_message = "Update napkin notes"
    print("💾 Committing changes to napkin repository...")
    rc, output = run_git_command(["commit", "-m", commit_message], napkin_path, check=False)
    if rc != 0:
        print(f"⚠️  git commit failed (napkin): {output}", file=sys.stderr)
        return rc

    print("📤 Pushing changes to napkin repository...")
    rc, output = run_git_command(["push"], napkin_path, check=False)
    if rc != 0:
        print(f"⚠️  git push failed (napkin): {output}", file=sys.stderr)
        return rc

    print("✅ Successfully committed and pushed changes to napkin repository")
    return 0
```
